# 发布说明（固定单文件流程）

发版说明统一维护在**一个固定文件**，不再为每个改动建独立片段文件：

- `changes.md`：**发版前**在这里写本次改动（覆盖即可，纯文本/多行，无需 front matter）。
  CI 会把它作为本次 Release 的说明。为空时回退到旧的片段机制，再为空则允许空说明。
- `archive.md`：发版成功后 CI 自动把 `changes.md` 内容**追加到本文件顶部**（带版本号与日期），
  并清空 `changes.md`，供下一次发版复用。所有历史版本累积在同一文件，不会无限膨胀成多文件。

`changes.md` 写法示例（按分类用 `## 标题` 分组，标题对齐以下中文；无分类的纯文本行默认归到「其他变更」）：

```markdown
## 新功能
- 持仓编辑默认按份额录入，UI 顺序调整为份额在前。

## 问题修复
- 修复刷新偶尔卡死的缺陷。

## 功能优化
- 周末/节假日沿用上一交易日数据，不再归零。
```

也可不写分类，直接逐行写，会自动归到「其他变更」：

```markdown
持仓编辑默认按份额录入。
周末沿用上一交易日数据。
```

支持的分类标题：`## 新功能` / `## 问题修复` / `## 功能优化` / `## 重要变更` / `## 其他变更`。

约束：

- 只写面向用户的具体中文说明，避免 `TODO`、笼统的重新打包说明。
- 发版后无需手动删除任何文件，`changes.md` 由 CI 自动清空，`archive.md` 自动累积。
- 本说明文件会永久保留。
